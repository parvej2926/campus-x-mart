# Roadmap

## Completed requirement-set items

- [x] Order integrity and item-status transitions are implemented and validated.
- [x] Messaging and notification privacy/read semantics are implemented and validated.
- [x] Admin-only report access is implemented without exposing server paths.
- [x] Local category prediction logic is implemented via the rule-based classifier and satisfies the project requirement without TensorFlow Lite.

The project now matches the original feature inventory for these items. The remaining roadmap items below cover operational hardening and later-stage product polish.

- Phase 1: safety net, config, hygiene, urgent security (this prompt).
- Phase 2, auth and abuse hardening: stop returning OTPs (only if APP_ENV=dev and EXPOSE_DEV_OTP=true); SMTP email delivery and pluggable SMS delivery without logging OTPs; max 5 attempts per code using verification_codes.attempt_count, plus a 60 s resend cooldown; UI resend button, remove "Demo codes" and pending_verification_codes from localStorage; rate limiting (slowapi) on login, register, verify, resend, assistant, upload; upload hardening (size cap, magic-byte check for jpeg/png/webp, remove the base64-in-DB fallback: dev = local uploads/ via StaticFiles, prod = signed Cloudinary upload); one-time WebSocket ticket instead of the JWT in the URL; server-side video_url validation (YouTube only).
- Phase 3, correctness and integrity (test-first; migrations in database/migrations/): sort keys price_asc, price_desc, newest, name_asc (the UI sends "price-asc", which the API silently ignores), stable tie-breaker, escape % and _ in search; item_media dedupe + UNIQUE(item_id, sort_order) + upsert on edit (each edit currently inserts a duplicate row and duplicates the card); orders: price set server-side from the item, only AVAILABLE items orderable, seller can decline a PENDING order, item becomes RESERVED on CONFIRMED and SOLD on COMPLETED and returns to AVAILABLE if a confirmed order is cancelled, at most one confirmed/completed order per item (partial unique index), SELECT ... FOR UPDATE on transitions; 404/409 instead of 500 (existence checks + FK/unique violation handlers), soft-delete items that have orders; reviews only from buyers with a COMPLETED order, no self-review, return review text and a seller rating; GET reactions returns current_reaction; GET messages must not mutate, must validate the receiver, and must paginate; conversation list with last message + unread count; notifications: mark read, read-all, unread count, pagination; single seed path with real password hashes, a real ADMIN user, a categories table + GET /api/categories, unique index on locations.
- Phase 4, backend structure: split main.py into app/{core,db,schemas,routers,services}; connection pool + get_db dependency (commit/rollback); no async def doing blocking I/O; Decimal for money; response_models; Alembic baseline; structured logging with request IDs; hardened Dockerfile (non-root, healthcheck); pg_trgm/full-text search and an index on item_media(item_id); remove duplicated/dead code (ml/).
- Phase 5, frontend: split App.jsx (pages/components/hooks/api client); React Router (/items/:id, /sell, /items/:id/edit, /my-listings, /orders, /messages, 404); TanStack Query; AuthContext with auto-logout on 401; toasts instead of alert(); server-side sort/filter only; readable condition/status labels; categories from the API; show the user's own reaction; ONE chat WebSocket for the app lifetime (selected user in a ref, guard onclose by socket identity, reconnect with backoff) and load messages for the auto-selected conversation; edit/delete/mark-sold UI, seller info and "Message seller" on the item page, unread badges; accessibility (label/htmlFor, buttons instead of clickable divs, aria-labels on stars and like buttons, focus states); YouTube ID parsing + iframe sandbox; lazy images; mobile nav; page title/favicon; error boundary; Vitest + Testing Library for login, browse and sell flows.
- Phase 6, product features and polish: campus email-domain allowlist (ALLOWED_EMAIL_DOMAINS); password reset; refresh tokens in an httpOnly cookie (user_sessions table); per-listing conversations; seller profiles; favorites; multiple images; offers; report/block plus an admin moderation dashboard on the existing reports table; real-time notifications over WebSocket; AI: category suggestion in the sell form (small scikit-learn model trained on items, with whole-word keyword fallback) and a natural-language search assistant that maps to filters, honestly labelled AI vs rule-based; price/condition/location filters; Leaflet + OpenStreetMap using locations.latitude/longitude; docker-compose (db + api + web), pre-commit, README rewrite (screenshots, architecture diagram, demo accounts), align PROJECT_CHECKLIST.md with reality, rename feaures.md.
